What are dig and nslookup?

DNS translates human-readable domain names (e.g. example.com) into IP addresses. dig and nslookup are the two most common CLI tools for DNS queries and troubleshooting.

Quick Start

# dig basic queries dig example.com A # IPv4 address dig example.com MX # mail server dig @8.8.8.8 example.com A # query via Google DNS dig example.com A +short # short output only dig example.com A +trace # trace resolution path # nslookup basic queries nslookup example.com # basic lookup nslookup example.com 8.8.8.8 # use specific DNS server nslookup -type=MX example.com # MX record lookup

dig Syntax

dig [@server] [name] [type] # @server — DNS server to query (optional, defaults to /etc/resolv.conf) dig @8.8.8.8 example.com # name — domain to query dig example.com # type — A / AAAA / MX / TXT / CNAME / NS / SOA / PTR / ANY dig example.com MX

Common Examples

# A record (IPv4 address) dig example.com A # AAAA record (IPv6 address) dig example.com AAAA # MX record (mail server) dig example.com MX # TXT record (SPF/DKIM) dig example.com TXT # CNAME record (alias) dig www.example.com CNAME # NS record (nameserver) dig example.com NS # SOA record (authority) dig example.com SOA # ANY record (all records) dig example.com ANY # Query via Cloudflare DNS dig @1.1.1.1 example.com A +short # Reverse lookup (PTR) dig -x 93.184.216.34 # Trace resolution path dig example.com A +trace # Batch query multiple domains dig +short example.com A google.com A cloudflare.com A

Output Structure

; <<>> DiG 9.18.1 <<>> example.com A ;# global options: +cmd ;# HEADER section — query info and flags ;# QUESTION SECTION — query (domain + type) ;# ANSWER SECTION — the actual result (most important) ;# AUTHORITY SECTION — authoritative servers ;# ADDITIONAL SECTION — extra info ;# Query time — lookup duration ;# SERVER — responding DNS server ;; ANSWER SECTION: example.com. 86400 IN A 93.184.216.34 # domain TTL class type IP address # (IN = Internet, 86400s = 24 hours)

nslookup Syntax

# Non-interactive mode (one-shot query) nslookup [name] [server] # Examples nslookup example.com # use default DNS nslookup example.com 8.8.8.8 # use Google DNS # Interactive mode (multiple queries) nslookup > server 8.8.8.8 # switch DNS server > set type=MX # set query type > example.com # run query > exit # exit

Common Examples

# Basic lookup (default DNS) nslookup example.com # Use specific DNS server nslookup example.com 1.1.1.1 # Query MX record nslookup -type=MX example.com # Query TXT record (SPF verification) nslookup -type=TXT example.com # Query NS record nslookup -type=NS example.com # Reverse lookup nslookup 93.184.216.34 # Debug mode (full response) nslookup -debug example.com

When to Use Which

dig — Use when:

  • Deep troubleshooting — need TTL, authority info
  • Tracing resolution path (+trace)
  • Batch querying multiple domains in scripts
  • Need +short simplified output
  • Specifying timeout (+time=2)
  • Querying SOA, ANY, or exotic record types

nslookup — Use when:

  • Quickly verifying a domain resolves
  • No dig installed (e.g. Windows out of box)
  • Interactive session — multiple queries
  • Checking DNS server response time
  • Simple reverse lookups

DNS Troubleshooting Flow

1
ping example.com
Verify DNS resolution. Success = domain resolves to IP. Failure = cannot resolve, continue to step 2.
2
nslookup example.com or dig example.com A +short
Confirm the DNS resolution result. Check if returned IP matches expectation.
3
dig @8.8.8.8 example.com A vs dig @1.1.1.1 example.com A
Compare results from multiple DNS servers. Different results = some server has stale/wrong cache.
4
dig example.com A +trace
Trace resolution path from root servers. Identifies where resolution fails.
5
dig example.com A +noall +answer +ttlid
Check TTL values. High TTL = changes take long to propagate. Low TTL = fast propagation but more frequent lookups.

Flush DNS Cache

After fixing DNS issues, you may need to flush local DNS cache to force fresh resolution.

OSCommand
Windowsipconfig /flushdns
macOSsudo dscacheutil -flushcache
Linux (systemd)sudo systemd-resolve --flush-caches
Linux (nscd)sudo service nscd restart
