DNS 多层缓存机制

当您访问一个域名时，DNS 解析结果会在多个层级被缓存。了解这些缓存层对于理解为什么 DNS 变更不能立即生效至关重要。

缓存层级详解

1
浏览器缓存
Chrome: chrome://net-internals/#dns
TTL: 5min-24h
2
操作系统 DNS 缓存
Windows: ipconfig /displaydns | Linux: systemd-resolved
TTL: 30s-10min
3
本地 DNS 服务器 (ISP/自建)
递归解析器，如 114.114.114.114, 8.8.8.8
TTL: 1-24h
4
权威 DNS 服务器
域名注册商/NS提供商，如阿里云、CloudFlare
TTL: 可设置
关键理解

DNS 变更后，旧记录会在各层缓存中保留直到 TTL 过期。这就是为什么修改 DNS 记录后，可能需要 5 分钟到 48 小时才能完全生效。

清除 DNS 缓存命令

Windows PowerShell
# 查看 DNS 缓存 ipconfig /displaydns # 清除 DNS 缓存 ipconfig /flushdns # 查看所有网络适配器信息 ipconfig /all
Linux
# 清除 systemd-resolved 缓存 sudo systemd-resolve --flush-caches # 重启 nscd sudo systemctl restart nscd # 查看 hosts 文件 cat /etc/hosts
macOS
# 清除 DNS 缓存 sudo dscacheutil -flushcache sudo killall -HUP mDNSResponder

DNS 传播延迟详解

DNS 传播是指 DNS 记录从权威服务器扩散到全球递归DNS服务器的过程。这个过程受到多种因素影响。

影响传播时间的因素

因素说明影响程度
TTL 值DNS 记录缓存时间，值越高传播越慢高
DNS 服务商不同厂商同步速度差异大中
地理位置距离权威服务器越远更新越慢中
 
DNS 变更后时间线:
T=0        权威 DNS 服务器已更新
T+5min     ISP DNS 缓存开始陆续过期
T+15min    操作系统 DNS 缓存过期
T+5min~24h 部分用户浏览器缓存过期
T+24~48h   绝大多数用户都能看到新记录

总结: DNS 变更可能需要 5分钟 到 48小时 才能完全生效

DNS 传播时间参考

场景最短最长典型值
同一 DNS 服务商内即时5分钟1-2 分钟
跨 DNS 服务商即时48小时2-4 小时
DNSSEC 生效即时72小时24 小时
CDN 配置变更即时48小时4-8 小时

DNS 修改最佳实践

第一步：提前降低 TTL 值

在计划修改 DNS 前 48 小时，将 TTL 降低到 300 秒（5分钟），这样变更可以更快传播。

第二步：执行 DNS 修改

在低峰期执行修改，减少影响范围。

第三步：验证修改

使用多个 DNS 服务器验证解析结果。

验证命令
nslookup example.com 8.8.8.8 nslookup example.com 1.1.1.1
第四步：恢复 TTL 值

确认修改生效后，将 TTL 恢复到正常值（3600 秒或更长）以减少解析延迟。

重要提示

如果 DNS 修改涉及 IP 变更，请确保旧服务器在变更期间保持运行，建议保留至少 24 小时后再下线。

路由表与 DNS 的关系

DNS 和路由表虽然都涉及网络地址，但工作在不同的层级，有不同的作用。理解它们的区别和协作关系对于网络故障排查非常重要。

┌────────────────────────────────────────────────────────────────┐
│                    DNS vs 路由表 核心区别                       │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   DNS (域名系统)              路由表 (路由表)                    │
│   ─────────────────          ──────────────────               │
│   工作层级: 应用层(第7层)     工作层级: 网络层(第3层)            │
│   处理内容: 域名 → IP         处理内容: IP → 路径               │
│   查找方式: 按名称查找         查找方式: 按目的网络查找           │
│   缓存机制: TTL               缓存机制: 无(实时)                │
│   变更影响: 解析结果           变更影响: 转发路径                 │
│                                                                │
└────────────────────────────────────────────────────────────────┘

DNS 与路由表的协作流程

用户请求: 访问 www.example.com

1. DNS 解析 (应用层)
   └─ www.example.com → 93.184.216.34

2. 路由决策 (网络层)
   └─ 目的 IP: 93.184.216.34
   └─ 查询路由表找到下一跳: 192.168.0.1
   └─ 数据包转发到下一跳

3. 数据包到达目标
   └─ 经过多跳路由后到达 93.184.216.34

常见路由表命令

Windows
# 查看路由表 route print # 查看 IPv4 路由表 netstat -r # 添加静态路由 route add 10.0.0.0 mask 255.0.0.0 192.168.0.1 # 删除静态路由 route delete 10.0.0.0 # 添加持久路由 route -p add 10.0.0.0 mask 255.0.0.0 192.168.0.1
Linux
# 查看路由表 ip route show route -n # 添加静态路由 sudo ip route add 10.0.0.0/8 via 192.168.0.1 # 删除静态路由 sudo ip route del 10.0.0.0/8 # 查看路由缓存 ip route show cache

目的网络子网掩码下一跳/接口说明
192.168.1.0255.255.255.0192.168.1.1 (LAN)本地网络
10.0.0.0255.0.0.010.0.0.1 (VPN)VPN 网络

关键理解

DNS 告诉您"目的地在哪"，路由表告诉您"怎么去目的地"。两者协同工作：DNS 提供目标 IP，路由表决定转发路径。
