什么是 Referer？

Referer 是 HTTP 请求头之一，告诉服务器用户从哪个页面导航过来。 注意：这是 Referrer 的拼写错误，历史上一直沿用。 

Referer: https://example.com/search?q=keyword

Referrer vs Referer

术语含义使用场景
Referrer 正确的拼写 描述网页访问的来源（名词）
Referer HTTP 头部的错误拼写 HTTP 请求头字段名（历史原因）

快速参考表

场景是否发送 Referer说明
HTTPS → HTTPS ✅ 发送 发送完整 URL
HTTPS → HTTP ❌ 不发送 安全限制，防止信息泄露
HTTP → HTTP ✅ 发送 发送完整 URL
地址栏直接输入 ❌ 不发送 没有来源页面
rel="noreferrer" ❌ 不发送 链接明确要求不发送
表单提交 ✅ 发送 POST 请求也会携带
fetch / XHR ✅ 发送 JavaScript 请求默认携带
file:// 协议 ❌ 不发送 本地文件安全限制

关键结论

安全边界
HTTPS → HTTP 不发送 Referer，防止敏感信息泄露到不安全连接
历史遗留
Referer 是 HTTP 头部的拼写错误，正确拼写是 Referrer
可控性
通过 Referrer-Policy 可精确控制 Referer 的发送范围和内容
不可信任
Referer 可以被伪造，不要仅依赖它做安全验证

Referrer-Policy 9 种策略

no-referrer
从不发送 Referer
不发送任何 Referer
no-referrer-when-downgrade
HTTPS→HTTP 不发送；其他发送完整 URL（默认）
HTTPS→HTTP: 不发送
其他: 完整 URL
origin
只发送 origin（协议+域名+端口）
https://example.com/
origin-when-cross-origin
同源发送完整 URL；跨域只发送 origin
同源: 完整 URL
跨域: origin
same-origin
同源发送完整 URL；跨域不发送
同源: 完整 URL
跨域: 不发送
strict-origin
只发送 origin；HTTPS→HTTP 不发送
HTTPS→HTTP: 不发送
其他: origin
strict-origin-when-cross-origin
同源完整 URL；跨域 origin；HTTPS→HTTP 不发送
同源: 完整
HTTPS→HTTP: 不发送
跨域: origin
unsafe-url
始终发送完整 URL（不安全）
完整 URL（含 query）

设置方法

HTTP 响应头

Referrer-Policy: strict-origin-when-cross-origin

HTML meta 标签

<meta name="referrer" 
   content="strict-origin-when-cross-origin">

链接属性

<a href="..." 
   referrerpolicy="strict-origin"
   rel="noreferrer">链接</a>

JavaScript

fetch(url, {
  referrerPolicy: 'strict-origin'
});

策略选择建议

场景推荐策略原因
需要分析流量来源 no-referrer-when-downgrade 默认策略，兼顾安全和功能
敏感页面（金融、医疗） strict-origin 只暴露域名，不暴露路径
需要完整 URL 做调试 origin-when-cross-origin 同源完整 URL，跨域保护
完全不需要 Referer no-referrer 最大化隐私保护
内网系统（无 HTTPS→HTTP 场景） unsafe-url 仅在内网使用，避免敏感泄露

常见使用场景

📊 流量分析

统计用户从哪些来源页面访问，了解流量渠道（如 Google 搜索、社交媒体）

🛡️ 防盗链

检查 Referer 防止其他网站直接链接你的图片、视频等资源，节省带宽

🔒 安全验证

根据 Referer 设置访问权限（如 API 限制仅允许特定域名访问）

HTTPS → HTTP 安全限制示意

🔒 HTTPS 页面
https://secure.com/page?q=token123
→
Referer 被浏览器拦截
🔓 HTTP 页面
http://insecure.com/page

原因：防止 HTTPS 页面中的敏感信息（如认证 token、查询参数中的用户数据）通过 Referer 泄露给不安全的 HTTP 连接。

HTTPS → HTTPS 正常发送

🔒 HTTPS 页面
https://a.com/product?id=123
→
Referer: https://a.com/product?id=123
🔒 HTTPS 页面
https://b.com/checkout

原因：两个安全连接之间没有信息泄露风险，Referer 可以正常传递。

安全注意事项

⚠️ Referer 可被伪造

攻击者可以随意设置 Referer 头部。永远不要仅依赖 Referer 做安全验证！

⚠️ URL 中的敏感信息

Referer 会暴露 URL 路径和查询参数。?token=xxx、/user/123/profile 等可能泄露。

✅ 安全最佳实践

  • 使用 no-referrer-when-downgrade（默认）作为起点
  • 敏感操作使用 POST 而非 URL 参数传递敏感数据
  • 登录后 URL 避免包含 session ID 或 token
  • 使用 CSRF Token 而非 Referer 验证
  • 敏感页面设置 strict-origin Referrer-Policy
