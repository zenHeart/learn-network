Kong API Gateway 完全指南

理解 Kong 网关的核心概念与快速部署

什么是 Kong？

Kong 是一个云原生、可扩展的 API 网关，基于 NGINX 构建，提供高性能的 API 管理能力。

🔀 智能路由
基于 Host、Path、Method 等条件将请求路由到不同上游服务
🔐 安全认证
支持 API Key、JWT、OAuth2、Basic Auth 等多种认证方式
⚡ 限流保护
保护上游服务免受过载，支持本地/Redis/PG 限流策略
📊 日志监控
请求日志、Prometheus 指标、健康检查

核心概念

概念说明类比
Service 上游服务的抽象 餐厅的厨房
Route 请求到 Service 的映射规则 服务员把订单送到哪个厨房
Consumer API 使用者（用户/应用） 餐厅顾客
Plugin 请求/响应处理逻辑 安保/收银/点菜系统

请求流程

👤 Client
HTTP/HTTPS
→
🦍 Kong Gateway
路由/认证/限流
→
🖥️ Upstream
真实服务
Client → Kong（处理 Plugin）→ Upstream（返回）→ Kong（处理 Plugin）→ Client

关键结论

高性能
基于 NGINX，Kong 可处理每秒数万请求，延迟极低
插件化
丰富的官方/社区插件，无需重复造轮子
可视化
可选 Konga 提供 Web UI，降低管理复杂度
K8s 原生
支持 Kubernetes Ingress，可声明式配置

配置优先级

优先级配置来源说明
1 (最高) Admin API 运行时动态配置
2 deck / Kong declarative config 声明式配置文件
3 Environment variables KONG_* 环境变量
4 (最低) kong.conf 配置文件默认值

5 步快速启动

创建 Docker 网络
让 Kong 和数据库容器互相通信
# 创建 bridge 网络 docker network create kong-net
启动 PostgreSQL 数据库
Kong 使用 PostgreSQL 存储配置数据
docker run -d \ --name kong-database \ --network=kong-net \ -p 5432:5432 \ -e POSTGRES_USER=kong \ -e POSTGRES_PASSWORD=kong \ -e POSTGRES_DB=kong \ postgres:13 # 等待 5 秒 sleep 5
初始化 Kong 数据库
运行数据库迁移，创建必要的表结构
docker run --rm \ --network=kong-net \ -e KONG_DATABASE=postgres \ -e KONG_PG_HOST=kong-database \ -e KONG_PG_USER=kong \ -e KONG_PG_PASSWORD=kong \ kong:latest kong migrations bootstrap
启动 Kong Gateway
暴露 8000（代理）和 8001（管理）端口
docker run -d \ --name kong \ --network=kong-net \ -p 8000:8000 \ -p 8443:8443 \ -p 8001:8001 \ -p 8444:8444 \ -e KONG_DATABASE=postgres \ -e KONG_PG_HOST=kong-database \ -e KONG_PG_USER=kong \ -e KONG_PG_PASSWORD=kong \ kong:latest
验证 Kong 运行状态
检查 Kong Admin API 是否响应
curl http://localhost:8001 # 应返回 JSON，包含 version 和 tagline 字段

一键启动（docker-compose）

version: '3.8'

services:
  kong-database:
    image: postgres:13
    environment:
      POSTGRES_USER: kong
      POSTGRES_PASSWORD: kong
      POSTGRES_DB: kong
    networks:
      - kong-net
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "kong"]
      interval: 5s
      timeout: 5s
      retries: 5

  kong-migration:
    image: kong:latest
    command: kong migrations bootstrap
    depends_on:
      kong-database:
        condition: service_healthy
    environment:
      KONG_DATABASE: postgres
      KONG_PG_HOST: kong-database
      KONG_PG_USER: kong
      KONG_PG_PASSWORD: kong
    networks:
      - kong-net

  kong:
    image: kong:latest
    depends_on:
      kong-migration:
        condition: service_started
    ports:
      - "8000:8000"
      - "8443:8443"
      - "8001:8001"
      - "8444:8444"
    environment:
      KONG_DATABASE: postgres
      KONG_PG_HOST: kong-database
      KONG_PG_USER: kong
      KONG_PG_PASSWORD: kong
    networks:
      - kong-net

networks:
  kong-net:
    driver: bridge

使用方法：docker-compose up -d

插件配置示例

启用 API Key 认证

# 1. 启用 key-auth 插件
curl -X POST http://localhost:8001/plugins \
  -d "name=key-auth" \
  -d "config.key_names=apikey,X-API-Key"

# 2. 创建 Consumer
curl -X POST http://localhost:8001/consumers \
  -d "username=my-app"

# 3. 为 Consumer 生成 API Key
curl -X POST http://localhost:8001/consumers/my-app/key-auth \
  -d "key=abc123-secret-key"

# 4. 请求时携带 Key
curl -H "apikey: abc123-secret-key" http://localhost:8000/your-route

启用限流（每分钟 100 次）

curl -X POST http://localhost:8001/plugins \
  -d "name=rate-limiting" \
  -d "config.minute=100" \
  -d "config.policy=local"

启用 CORS

curl -X POST http://localhost:8001/plugins \
  -d "name=cors" \
  -d "config.origins=*" \
  -d "config.methods=GET,POST,PUT,DELETE" \
  -d "config.headers=Content-Type,Authorization" \
  -d "config.credentials=true" \
  -d "config.max_age=3600"

插件执行阶段

请求生命周期中的插件执行点：

  1. SSL Certificate        ←--
  2. Access                 ←-- Plugin 逻辑主要在这里
  3. Header Filter          ←--
  4. Body Filter            ←--
  5. Log                    ←-- 记录日志/发送监控数据

每个插件可绑定到多个阶段：
- rewrite: 重写请求
- access: 认证/限流/路由决策
- header_filter: 修改响应头
- body_filter: 修改响应体
- log: 记录日志

自测题

1. Kong Gateway 的管理 API 默认端口是？
✅ 正确！8001 是 Kong Admin HTTP 端口，用于管理 Service/Route/Plugin
2. Kong 中，谁负责将请求路由到上游服务？
✅ 正确！Route 定义了请求如何路由到 Service，Service 是上游服务的抽象
3. 以下哪个不是 Kong 的认证插件？
✅ 正确！rate-limiting 是限流插件，不是认证插件
4. Kong 的数据存储支持哪些数据库？
✅ 正确！Kong 支持 PostgreSQL（默认）和 Cassandra 两种数据库
