文件句柄（File Descriptor）概念

什么是文件句柄？

文件句柄是 Linux 内核为进程分配的整数标识符，用于访问文件、网络连接、管道等资源。

💡 关键概念：文件句柄（FD）是内核层面的标识符，进程通过它与内核交互访问各种 I/O 资源。

标准文件描述符

每个进程启动时默认有三个标准文件描述符：

FD 名称 默认关联
0 stdin 标准输入（键盘）
1 stdout 标准输出（终端）
2 stderr 标准错误输出（终端）

FD 与 FILE* 的区别

文件句柄（FD）

内核层面的整数标识符，直接与系统调用交互

文件指针（FILE*）

C 标准库封装后的结构体，包含 FD 和缓冲区的信息

文件句柄可以指向什么？

  • 📄 普通文件
  • 📁 目录
  • 🔌 网络套接字（Socket）
  • Pipe/管道
  • ⌨️ 设备文件（/dev/...）
  • 🔊 终端（TTY）

lsof 命令详解

lsof（List Open Files）是最常用的查看进程打开文件的工具。

基本用法

lsof                    # 查看所有打开的文件
# 输出示例
COMMAND  PID  USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
init     1    root   0u   CHR  136,0  0t0      3  /dev/pts/0
sshd    1234 root   3u   IPv4 12345  0t0      TCP *:22 (LISTEN)

常用命令选项

选项 说明 示例
-p <PID> 查看指定进程 lsof -p 1234
-u <user> 查看指定用户 lsof -u root
-i 查看网络连接 lsof -i
-i:80 查看端口 lsof -i:80
+D <dir> 递归查看目录 lsof +D /tmp

FD 字段说明

FD 字段格式：数字 + 模式字母

  • u - 读/写模式打开
  • r - 只读
  • w - 只写
  • txt - 程序代码段
  • mem - 内存映射文件

实用案例

# 查看 SSH 连接
lsof -iTCP:22

# 查看某个用户的所有网络连接
lsof -u www-data -i

# 查看正在使用 /var/log/syslog 的进程
lsof /var/log/syslog

# 查看端口 443 上的进程（包含命令）
lsof -i:443 -P -n

# 找出打开文件最多的进程 TOP 5
lsof 2>/dev/null | awk '{print $2}' | sort | uniq -c | sort -rn | head -5

文件句柄限制配置

三级限制体系

🔧 系统级

kernel.filemax
所有进程的总限制

👤 用户级

ulimit -n
单个用户的限制

📦 进程级

RLIMIT_NOFILE
单个进程的限制

查看当前限制

# 查看系统最大 FD 数量
cat /proc/sys/fs/file-max
# 输出：65536

# 查看系统 FD 使用情况
cat /proc/sys/fs/file-nr
# 输出：1200  0  65536
# 含义：已分配 1200 | 分配但未使用 0 | 系统上限 65536

# 查看当前用户限制
ulimit -n
# 输出：1024

# 查看某个进程的限制
cat /proc/$$/limits
# 找到 "Max open files" 行

修改限制

临时修改（当前会话）

# 临时提高限制（会话说有效）
ulimit -n 65536

# 验证
ulimit -n

永久修改（用户级）

# 编辑 /etc/security/limits.conf
# 添加以下两行：
*               soft    nofile          65536
*               hard    nofile          65536

# 然后重新登录或执行
source /etc/security/limits.conf

永久修改（系统级）

# 临时
echo 200000 > /proc/sys/fs/file-max

# 永久 - 编辑 /etc/sysctl.conf
echo "fs.file-max = 200000" >> /etc/sysctl.conf
sysctl -p
⚠️ 注意：系统级限制需要 root 权限，修改后可能影响系统稳定性，请谨慎操作。

常见触发场景

📁 文件句柄泄露

打开文件后未正确 close()，常见于异常处理未释放资源

🌐 并发连接过多

Web 服务器同时处理大量请求，每个连接占用一个 FD

📝 日志未轮转

日志持续增长，打开大量日志文件描述符

各语言 FD 泄漏示例

Python（错误示例）

# ❌ 错误：打开文件未关闭
def read_files(filenames):
    results = []
    for filename in filenames:
        f = open(filename, 'r')  # 打开但 never close!
        results.append(f.read())
    return results

# ✅ 正确：使用 with 语句自动关闭
def read_files_correct(filenames):
    results = []
    for filename in filenames:
        with open(filename, 'r') as f:
            results.append(f.read())
    return results

Node.js（错误示例）

// ❌ 错误：未关闭文件流
const readFiles = async (filenames) => {
  const streams = filenames.map(f => fs.createReadStream(f));
  // streams 永不关闭!
  return Promise.all(streams.map(s => s.text()));
};

// ✅ 正确：使用 pipeline 或手动关闭
const readFilesCorrect = async (filenames) => {
  const results = [];
  for (const filename of filenames) {
    const stream = fs.createReadStream(filename);
    const content = await streamToString(stream);
    stream.close();  // 手动关闭
    results.push(content);
  }
  return results;
};

问题排查流程

错误现象

  • 日志中出现 "Too many open files" 错误
  • 新建连接失败（socket 申请 FD 失败）
  • 特定服务无法启动
  • 系统日志中出现 EMFILE 错误

排查步骤

# Step 1: 确认问题
cat /proc/sys/fs/file-nr
# 查看是否接近系统上限

# Step 2: 找出 FD 使用最多的进程
lsof 2>/dev/null | awk '{print $2}' | sort | uniq -c | sort -rn | head -10

# Step 3: 查看可疑进程
lsof -p <PID>

# Step 4: 检查网络连接（可能是 socket 泄露）
lsof -i | wc -l

# Step 5: 持续监控（观察 FD 增长趋势）
watch -n 1 'lsof -p <PID> | wc -l'

快速修复

# 方法1: 提高用户限制（临时）
ulimit -n 65536

# 方法2: 重启问题进程
kill -9 <PID>
# 或
systemctl restart <service>

# 方法3: 如果是文件泄露，查找未关闭的文件
lsof -p <PID> | grep -v "^COMMAND" | awk '{print $NF}' | sort | uniq -c | sort -rn | head

预防措施

✅ 使用 with/try-finally

确保资源在任何情况下都被释放

✅ 监控告警

设置 FD 使用率阈值，超限时告警

✅ 日志轮转

配置 logrotate 避免日志文件无限增长

✅ 连接池

使用连接池管理数据库/网络连接
