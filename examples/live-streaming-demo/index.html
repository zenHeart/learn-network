🔄 直播协议对比

不同的直播协议有不同的适用场景和特点：

RTMP (Real-Time Messaging Protocol)

实时 推流

延时： 1-3 秒

优点：

  • 低延迟，适合互动直播
  • Adobe 主导，广泛支持
  • TCP 可靠传输

缺点：

  • 非标准 HTTP，需要特殊端口
  • 移动端支持较差
  • 已被 Adobe 放弃维护

HLS (HTTP Live Streaming)

拉流 大规模分发

延时： 5-10 秒

优点：

  • 基于 HTTP/CDN，兼容性好
  • iOS/Android 原生支持
  • 抗网络抖动能力强

缺点：

  • 延迟较高
  • 切片文件需要时间
  • 首屏加载较慢

WebRTC (Web Real-Time Communication)

实时 低延时

延时： <300ms

优点：

  • 极低延迟
  • P2P 支持，节省带宽
  • 浏览器原生支持

缺点：

  • 复杂，需要 STUN/TURN 服务器
  • 不适合大规模直播
  • 移动端适配复杂

DASH (Dynamic Adaptive Streaming over HTTP)

拉流 自适应

延时： 5-15 秒

优点：

  • MPEG-DASH 国际标准
  • 自适应码率
  • 灵活的 DRM 支持

缺点：

  • 生态不如 HLS
  • 服务器配置复杂
协议 延时 适用场景 移动端支持
RTMP 1-3s 秀场直播、游戏直播 需 SDK
HLS 5-10s 赛事直播、教育直播 原生支持
WebRTC <300ms 视频通话、连麦互动 需适配
DASH 5-15s 点播、国际化内容 部分支持

📝 直播完整流程详解

1

📹 音视频采集

使用浏览器 MediaDevices API 或 native SDK 获取音视频流

2

🔧 音视频编码

将原始音视频数据编码压缩，常用编码器：

  • 视频：H.264/H.265/VP8/VP9/AV1
  • 音频：AAC/Opus/MP3
3

📤 推流协议封装

将编码后的数据封装成推流协议，如 RTMP、WebRTC

4

🖥️ 服务器处理

流媒体服务器接收推流后进行：

  • 转码（不同清晰度）
  • 录制存储
  • 截图封面
  • 分发路由
5

🌐 CDN 分发

通过 CDN 网络将内容分发到全球边缘节点

6

📥 观众拉流

观众端根据网络状况选择合适的拉流协议和清晰度

7

🎬 音视频解码播放

解码后通过 Video 标签或播放器渲染输出

💻 推流端示例代码

// 1. 获取媒体设备 const stream = await navigator.mediaDevices.getUserMedia({ video: { width: 1280, height: 720 }, audio: true }); // 2. 创建 Video 元素预览 const video = document.createElement('video'); video.srcObject = stream; await video.play(); // 3. 使用 RTMP SDK 推流 const rtmpPublisher = new RTMPPublisher({ appKey: 'your-app-key', streamKey: 'stream-key' }); rtmpPublisher.publish(stream); // 4. 监听状态 rtmpPublisher.on('statusChange', (status) => { console.log('推流状态:', status); });

🎥 拉流端示例代码

// 使用 HLS.js 播放 HLS 流 import Hls from 'hls.js'; const video = document.getElementById('video'); const url = 'https://example.com/live.m3u8'; if (Hls.isSupported()) { const hls = new Hls({ startLevel: -1 // 自动码率 }); hls.loadSource(url); hls.attachMedia(video); hls.on(Hls.Events.MANIFEST_PARSED, () => { video.play(); }); } else if (video.canPlayType('application/vnd.apple.mpegurl')) { // Safari 原生支持 HLS video.src = url; video.play(); }

模拟流程说明

阶段 耗时 说明
1. 设备初始化 ~500ms 请求摄像头、麦克风权限
2. 编码准备 ~300ms 初始化视频/音频编码器
3. 建立连接 ~800ms 连接 RTMP 服务器
4. 开始推流 ~200ms 首帧数据发送
5. 服务器处理 ~100ms 转码、分发
6. CDN 同步 ~2000ms 全球节点同步

真实直播延迟组成

总延迟 ≈ 编码延迟 + 推流延迟 + 服务器延迟 + CDN 延迟 + 解码延迟


HLS 直播 1-2s + 2-4s + 0.5s + 1-3s + 0.5s = 5-10s
RTMP 直播 1-2s + 0.5s + 0.5s + 0s* + 0.3s = 2-3s
WebRTC 直播 0.1s + 0.1s + 0.1s + 0s + 0.1s = <300ms

* RTMP 经过 CDN 会增加延迟
