核心原理速查

简单请求流程 1. 浏览器发送请求 └─ 自动带上 Origin: http://localhost:... 2. 服务器响应 ├─ Access-Control-Allow-Origin: * └─ （或具体 origin） 3. 浏览器检查 ACAO ├─ ✅ 匹配 → 响应交给 JavaScript └─ ❌ 不匹配 → 响应被拦截 ───────────────────── 预检请求流程 1. OPTIONS 预检请求 ├─ Access-Control-Request-Method: POST └─ Access-Control-Request-Headers: Content-Type 2. 服务器预检响应 ├─ Access-Control-Allow-Methods ├─ Access-Control-Allow-Headers └─ Access-Control-Max-Age: 86400 3. ✅ 预检通过 → 发送实际请求 4. 同简单请求流程处理实际响应
凭证请求关键约束 请求方： fetch(url, { credentials: 'include' }) 服务器必须同时设置： ✓ Access-Control-Allow-Origin = 具体 origin ✓ Access-Control-Allow-Credentials: true ✗ 不能使用 * 通配符 ───────────────────── 常见错误原因 1. 服务器未返回 ACAO 头 2. ACAO=* 但携带了 credentials 3. 预检请求被服务器拒绝（无响应/4xx） 4. 跨域重定向后 preflight 不支持 ───────────────────── 开发调试技巧 1. Chrome DevTools → Network └─ 过滤选项：选择 "Doc" + "Other" 2. 预检请求 Method 为 OPTIONS 3. 响应头带灰色的为 CORS 相关 4. Console 中橙色警告 = CORS 错误
