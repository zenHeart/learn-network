HTTP 请求方法对比

方法语义Body幂等典型场景
GET获取无✅查询列表、详情
POST创建有❌注册、登录、提交
PUT全量替换有✅完整更新资源
DELETE删除可选✅删除资源
PATCH部分更新有❌更新单个字段

GET 请求

// GET 带查询参数 GET https://api.example.com/users?page=1&limit=20 // Params 面板（Postman 自动拼接） page = "1" limit = "20"

POST 请求

POST https://api.example.com/users Content-Type: application/json { "title": "Hello", "body": "World", "userId": 1 }

PUT vs PATCH 对比

// PUT — 完整替换（包含所有字段） PUT /users/1 { "name": "Alice", "email": "a@b.com", "age": 25 } // PATCH — 部分更新（只改邮箱） PATCH /users/1 { "email": "new@b.com" }

Pre-request Script 示例

// 生成时间戳 const ts = Date.now(); pm.environment.set("timestamp", ts); // 动态签名（需 CryptoJS） const secret = pm.environment.get("signSecret"); const sign = CryptoJS.HmacSHA256(ts, secret); pm.environment.set("sign", sign); // 打印日志 console.log("Timestamp:", ts);

Tests 脚本示例

// 检查状态码 pm.test("状态码为 200", () => { pm.response.to.have.status(200); }); // 检查响应字段 pm.test("包含 user_id", () => { const data = pm.response.json(); pm.expect(data).to.have.property("user_id"); }); // 检查响应时间 < 500ms pm.test("响应快速", () => { pm.expect(pm.response.responseTime).to.be.below(500); });

常用 Chai 断言

pm.expect(x).to.equal(y) // 相等 pm.expect(x).to.be.a('string') // 类型检查 pm.expect(x).to.have.property('p') // 属性存在 pm.expect(x).to.include(y) // 包含 pm.expect(x).to.have.lengthOf(3) // 长度 pm.expect(x).to.be.above(10) // 大于 pm.expect(x).to.match(/regex/) // 正则匹配

嵌套请求 pm.sendRequest

pm.sendRequest({ url: '{{baseUrl}}/login', method: 'POST', body: { mode: 'raw', raw: JSON.stringify({ username: 'testuser', password: 'testpass' })} }, (err, res) => { if (!err) { const token = res.json().token; pm.environment.set('token', token); } });

Mock Server 工作原理

Mock Server 让你在真实后端 API 完成之前，就能模拟返回预设数据，前端可并行开发。

📱 前端应用 → 🎭 Mock Server
postman.com/mock/... → 📋 Example 响应

Example（示例响应）配置

// GET /users/:id — 200 OK Status: 200 { "id": 1, "name": "Alice", "email": "alice@example.com" } // GET /users/:id — 404 Not Found Status: 404 { "error": "User not found", "code": 404 } // 分页响应 Example Status: 200 { "data": [...], "pagination": { "page": 1, "total": 100 } }

Mock Server 使用场景

场景说明
前端并行开发后端 API 还没好，前端用 Mock 先跑
接口测试隔离使用 Mock，不依赖真实 API
演示 / POC快速演示 API 功能
边界情况测试Mock 各种错误码（404/500/429）

1. 变量命名规范

// 推荐：清晰的分层命名 {{env}}_{{module}}_{{field}} {{baseUrl}} {{dev_userService_baseUrl}}

2. Collection Pre-request 统一认证

// Collection 的 Pre-request Script 中： const token = pm.environment.get("accessToken"); if (token) { pm.request.headers.add({ key: "Authorization", value: `Bearer ${token}` }); }

3. pm.setNextRequest 控制执行顺序

pm.test("检查是否需要登录", () => { const data = pm.response.json(); if (data.needLogin) { postman.setNextRequest("POST /login"); } else { postman.setNextRequest("GET /profile"); } }); // null 表示停止执行 postman.setNextRequest(null);
