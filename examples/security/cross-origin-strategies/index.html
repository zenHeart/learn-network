同源策略：浏览器的安全基石

浏览器同源策略（Same-Origin Policy）是 Web 安全的核心机制，限制了一个源的文档或脚本与另一个源的资源交互。

同源的三个要素

协议 + 域名 + 端口 → 同源

同源策略限制了什么

  • AJAX / fetch 请求无法跨域
  • 无法读写不同源的 Cookie / LocalStorage
  • 无法访问不同源 iframe 的 DOM
  • <script>、<link>、<img> 可嵌入（但访问受限）

CORS：跨域资源共享

通过 HTTP 响应头授权，是目前最标准、最安全的跨域方案。

简单请求流程

// 浏览器自动在请求头添加 Origin
GET /api/data HTTP/1.1
Origin: https://frontend.com
Host: api.example.com

// 服务器响应头声明允许的来源
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://frontend.com
Content-Type: application/json

{"data": "hello"}

预检请求（Preflight）

// 非简单请求（如 PUT、DELETE、JSON）先发 OPTIONS 预检
OPTIONS /api/data HTTP/1.1
Origin: https://frontend.com
Access-Control-Request-Method: PUT

// 服务器响应
HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://frontend.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Max-Age: 86400

Node.js Koa 响应头

async function cors(ctx, next) {
  ctx.set('Access-Control-Allow-Origin', ctx.env === 'prod'
    ? 'https://yourdomain.com'
    : '*');
  ctx.set('Access-Control-Allow-Credentials', 'true');
  ctx.set('Access-Control-Allow-Methods', 'GET,POST,PUT,DELETE,OPTIONS');
  ctx.set('Access-Control-Allow-Headers', 'Content-Type,Authorization');
  if (ctx.method === 'OPTIONS') { ctx.status = 204; return; }
  await next();
}

优点

  • 支持所有 HTTP 方法
  • 支持请求头/响应头自定义
  • 支持 Cookie 携带
  • 语义清晰，安全性高

缺点

  • 需要服务器配合
  • 预检请求增加延迟
  • IE10 以下不支持
  • * 不可与 credentials 共用

JSONP：古老的跨域hack

利用 <script> 标签不受同源限制的特性，已不推荐使用。

原理

// 1. 前端定义回调函数
function handleResponse(data) { console.log(data); }

// 2. 动态创建 script 标签
const script = document.createElement('script');
script.src = 'https://api.example.com/data?callback=handleResponse';
document.body.appendChild(script);

// 3. 服务器返回: handleResponse({"name":"Alice","age":30})

简易实现

function jsonp(url, params, callback) {
  const cb = 'cb_' + Date.now();
  window[cb] = callback;
  const q = new URLSearchParams({ ...params, callback: cb });
  const s = document.createElement('script');
  s.src = `${url}?${q}`;
  s.onload = () => s.remove();
  document.body.appendChild(s);
}

postMessage：安全的窗口通信

允许跨窗口、跨域发送消息，是 iframe 通信的首选方案。

基本用法

// 发送消息到目标窗口
targetWindow.postMessage({ type: 'AUTH', token: 'abc123' }, 'https://target-origin.com');

// 监听消息（必须验证来源）
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://expected-origin.com') return;
  console.log('收到消息:', event.data);
});

父子窗口通信示例

// 父窗口
const iframe = document.querySelector('iframe');
iframe.contentWindow.postMessage({ type: 'PING' }, 'https://child.com');

// 子窗口
window.addEventListener('message', (e) => {
  if (e.origin !== 'https://parent.com') return;
  if (e.data.type === 'PING') {
    e.source.postMessage({ type: 'PONG' }, e.origin);
  }
});

WebSocket：全双工实时通信

不受同源策略限制，建立连接后服务端可主动推送。

握手过程

// 1. HTTP 升级请求
GET /ws HTTP/1.1
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==

// 2. 服务器 101 响应
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade

客户端 API

const ws = new WebSocket('wss://api.example.com/ws');

ws.onopen = () => { ws.send(JSON.stringify({ type: 'subscribe', ch: 'news' })); };
ws.onmessage = (e) => { console.log('收到:', JSON.parse(e.data)); };
ws.onerror = (e) => { console.error('错误', e); };
ws.onclose = () => { console.log('连接关闭'); };

代理方案：最干净的生产方案

通过同域代理转发请求，对前端代码无侵入，是生产环境的最佳选择。

nginx 反向代理

server {
    listen       80;
    server_name  frontend.com;

    location /api/ {
        proxy_pass         http://backend-api.com/;
        proxy_set_header   Host            api.example.com;
        proxy_set_header   X-Real-IP       $remote_addr;
    }

    location /ws/ {
        proxy_pass         http://ws-server.com/;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade    $http_upgrade;
        proxy_set_header   Connection "upgrade";
    }
}

Vite 开发代理

// vite.config.js
export default {
  server: {
    proxy: {
      '/api': {
        target:       'http://localhost:3000',
        changeOrigin: true
      }
    }
  }
};

方案对比与选型

方案方向请求安全场景
CORS双向任意高RESTful API（首选）
WebSocket双向任意高实时通信、游戏、推送
postMessage双向任意高*iframe 嵌入通信
nginx 代理双向任意高生产环境 API
JSONP单向GET中不推荐
document.domain单向任意中主域相同的子域
location.hash单向GET低不推荐

* postMessage 安全性取决于开发者是否正确验证 event.origin

选型决策树

需要调用后端 API？
├── 是 → 生产环境？ → 是 → nginx 反向代理
│                    └─ 否 → CORS
├── 需要实时双向通信？ → 是 → WebSocket
├── iframe 嵌入通信？ → 是 → postMessage
└── 遗留系统（仅 GET）？ → 是 → JSONP（不推荐，尽快迁移）
